# アンリミテッド解放

ホーム画面のギルドボタンが，アンリミテッドの構築制限を外すスイッチになっています．押すたびにオンとオフが入れ替わり，オンの間は次が変わります．

- リサージェントカードがアンリミテッドで使えます
- 同名カードを1枚のデッキに40枚まで入れられます
- デッキ編集のカード一覧に全クラスのカードが並びます

デッキの40枚上限は変わらず，ローテーションなど他のフォーマットにも影響しません．

## 使い方

ホームでギルドを押すと，ギルド検索の一覧に1件だけ「アンリミテッド解放: ON」または「OFF」と出ます．これが今の状態で，戻したいときはホームに戻ってからもう一度ギルドを開いてください．

反転するのはホームから入ったときだけです．「申請中」タブが `GuildApply.OpenCategory` から `guild/info` を投げ直すため，受信するたびに反転させるとタブを覗いただけで元へ戻ります．

状態はプレイヤーごとにサーバーへ保存されるため，同じホストで遊ぶ他の人には影響しません．

## 反映のタイミング

クライアントはカードマスターと `load/index` をログイン時に一度だけ読み，以降は読み直しません．そのため切り替えた直後の画面にはまだ反映されておらず，一覧の表示も「(未反映)」になります．

ホームに戻るとダイアログが出るので，タイトルへ戻るを押すと入り直したところで反映されます．文面はログインボーナスのものが出ますが，ボタンの動作は `SoftwareReset.exec()` で，これがサーバーから踏める唯一のログインやり直しの経路です．

## ギルド画面のボタン

ギルドは実装していないため，画面内のボタンは押しても何も起きません．作成・参加・招待・脱退・チャットはすべて `result_code` 2054 (`GUILD_MAINTENANCE`) を返しており，クライアントはメンテナンス中のダイアログを出して閉じます．一覧の取得だけは空で正常に返すので，タブを見て回るぶんにはダイアログは出ません．

`feature_maintenance_list` に2054を入れるとボタン自体をグレーにできます (`MaintenanceButton` が `SetObjectToGrey` を呼び，コライダーごと無効化されます)．ただしどのボタンにその部品が付いているかはシーン側の情報で，ホームのギルドボタンに付いていた場合はスイッチごと押せなくなります．

## 全クラスのカード

クライアントはカードマスターを2つ持ちます (`CardMaster.CardMasterId` の `Default` と `NextCardMaster`)．デッキ編集を含む構築系の画面はすべて `Default` に固定されている一方，対戦がどちらを使うかは `DoMatchingBase.SettingCardMasterId` がマッチング応答の `card_master_id` から決めます．

そこで，オンのときは1番の `clan` 列を全て0にして配り，2番は元のまま配ります．デッキ編集のクラスフィルタは `(mask & 1 << card.Clan) != 0` で，マスクには常にニュートラルのビット0が立っているため，全カードがどのクラスのデッキにも並びます．

`card_master_id` はオンオフに関わらず常に2を送ります．2番はどちらの配信でも無加工なので，オフのプレイヤーには何も変わりません．オンのプレイヤーだけに送ると，切ってから再ログインするまでの間，平坦化された1番で対戦することになります．

副作用があります．

- デッキ編集でクラスの絞り込みボタンを押すと一覧が空になります．ビット0を立てるのは中立ボタンだけで，クラスボタンは `1 << MainClass` を作りますが，全カードの `clan` が0のためどれも一致しません．「全て」を押せば戻ります
- カード一覧画面のクラスタブも同じ理由で空になり，無指定なら全部出ます
- 対戦以外の画面では，カードのクラスアイコンと枠がニュートラル表示になります
- CP対戦は `PracticeDeckSelectConfirmDialog` が対戦マスターを `Default` に戻すため1番を使い，クラスを参照するカードが正しく動きません

## 仕組み

| 制限 | クライアントでの持ち方 | サーバーから動かせるか |
| --- | --- | --- |
| リサージェント禁止 | カードマスターの `IsResurgentCard` 列 | 動かせる |
| 同名3枚 | `UnlimitedFormatBehavior` の定数．ただしカードごとに `load/index` の `unlimited_restricted_base_card_id_list` が上書きする | 上書き経由で動かせる |
| クラス制限 | `FilterController` がデッキのクラスから組み立てる | マスクは動かせないが，`clan` 列を0にすれば通る |
| デッキ40枚 | `UnlimitedFormatBehavior.DeckCardNumMax` の定数 | 動かせない |

`unlimited_restricted_base_card_id_list` はナーフ用の経路で，カードごとの上限を3より下げるためのものです．下限の検査がないので上げる方向にも使え，オンのときは全base_card_idを40で配ります．

所持枚数も同時に40へ上げています．デッキ編集は所持数を超えて入れられないため，上限だけ上げても3枚で止まるからです．

## デッキコード

カードIDの並びからデッキコードを作れるので，編集画面を通さずにデッキを組めます．

```bash
curl -s -X POST http://localhost/openverse/deckcode -H 'Content-Type: application/json' -d '{"clan":1,"deck_format":2,"cardID":[100114010,100211010,100311010]}'
```

`clan` はデッキのクラス (1=エルフ，2=ロイヤル，3=ウィッチ，4=ドラゴン，5=ネクロ，6=ヴァンプ，7=ビショップ，8=ネメシス) で，リーダーがこれになります．`deck_format` は2がアンリミテッドです．クラスに0は入れられません．`DataMgr.SetClassPrm` が1から8の範囲外を捨てるため，リーダーを引くところで落ちます．

取り込み側 (`DeckCreateMenuUI`) はカードがマスターに存在するかしか見ておらず，クラスも枚数も検査しません．
